## What this run established

- All three client requests received HTTP 200. The first two included both the
  expected finish reason and `[DONE]`; the third reached transport EOF without
  either, as the mock was instructed to do. The result pattern was
  `stream_complete=[true,true,false]`.
- The circuit-breaker counter recorded three `outcome="success"` values. Its
  success definition therefore cannot stand in for intended stream completion
  in this path. This is a boundary of that metric, not a claim that the circuit
  breaker is defective.
- Three policy debug messages reported `matched_chars=0,input_chars=0`, although
  the repeated chat requests had nonempty messages. The source's regular HTTP
  chat extractor uses `session_params.session_id` or an empty string, not message
  text. See [the pinned extractor](https://github.com/vllm-project/router/blob/1d10e71fb7bb4c0adc9f2c16ec77bf5dd4aa1586/src/protocols/spec.rs#L535-L559).
- Client arrival of a nonempty content delta was recorded separately from
  headers, heartbeat/role-only events and EOF. The injected 50 ms pauses make
  these boundaries visible; their numeric timings are not a router benchmark.
- Request IDs were generated by the client and forwarded to the worker. There
  is no native policy-attempt identity in this capture. No normalized analyzer
  export was constructed, and no policy log was joined by time or line order.

The router's local policy model key is `default`; the synthetic request body
uses `mock-model`. Preserve those different fields instead of manufacturing
engine/model identity from the log.
