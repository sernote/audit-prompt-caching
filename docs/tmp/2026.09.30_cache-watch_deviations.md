Each entry: expected vs observed, evidence, action, remaining risk.

- Observed: not on `PATH` in this Claude session. A Codex `apply_patch`
  binary exists under the Codex tmp `arg0` directory and accepts a patch on stdin.
- Action: all manual edits go through that binary by absolute path.

## 4. Parent design corrections during the work (plan deviation)

## 5. My own catch-up test contradicted the cap

- Expected: the first test draft asserted that the day-21 window stayed at the day-6 cap.
- Observed: that freezes an ever-growing window; a bounded cap must slide with `T`.
- Action: the test now asserts day 21 is capped at day 7 and a day-60 repeat is
  capped at day 46, with the gaps merged into one entry from `T0`.
- Risk: none.

## 6. Flaky tests: run token could start with `-`

- Expected: deterministic tests.
- Observed: intermittent failures in different tests (for example, `KeyError:
  'snapshot'`) about once in 20 runs. `secrets.token_urlsafe` can start with
  `-`, and argparse then reads `--token -abc` as an option.
- Action: tokens use `secrets.token_hex` (never starts with `-`). 25 repeated
  suite runs were clean afterwards.
- Risk: none known. Reservation tokens were already hex.

## 7. Test clock bug before the test-clock mode

  `--now` entirely (item 4).

## 12. Fix round: final review findings 1-3 (2026-09-30)

Source: `/tmp/cache-watch-final-review.txt`. The parent validated findings
1-3. Finding 4 (bytecode) is pre-commit hygiene that the parent performs.
Failing sources stay enabled.

- **Alias identity (finding 1).**
  - Expected by the earlier spec: "a different change on the same URL has a
    different binding".
  - Observed: false for one release or one snapshot diff holding two changes.
    An alias match under a different key overwrote an `implement` outcome
    with `watch`, or absorbed the change into unrelated reserved work as
    `duplicate_active`.
  - Action: a shared alias under a different key now returns
    `alias_conflict` (exit 3), which changes no candidate. A triage under the
    existing key still merges. Change-scoped aliases (`@<binding>#<topic>`)
    are accepted; an empty topic is refused. The run records conflicts, a
    later triage of either key resolves them, and `finish-run` lists
    `unresolved_conflicts`. The `ambiguous_match` path is gone because every
    multi-owner case is now a conflict.
  - Two old tests required silent merging of different keys. They now reuse
    the existing key, which is the documented way to merge.
- **Durable backlog (finding 2).**
  - Observed: `failed` or `released` implement candidates, and ones never
    dispatched because of capacity, dropped out of `attention`. Snapshot
    promotion or the window moving on then lost them.
  - Action: `attention` now lists `dispatch backlog: <status>, attempt <n>`
    for every inactive, unmerged `implement` candidate without
    `needs_decision`.
  - `attempts_exhausted` now sets `needs_decision` and appends a history
    event. The dispatch record is kept as evidence.
  - The runbook processes the backlog daily, independent of source deltas.
    Merged work is never listed.
- **Shell quoting (finding 3).**
  - Observed: `zsh -c 'print -r -- repos/vllm-project/vllm/releases?per_page=30'`
    gives `no matches found`, exit 1. The quoted form prints the path and
    exits 0.
  - Action: all 10 `gh api` extraction strings in `sources.json` are quoted.
    The runbook quotes the path and pages with `&page=N`.
  - `validate-registry` refuses an unquoted `gh api` path containing `?`. A
    test also checks the runbook.
  - The runbook now says that shell functions and variables do not persist
    across exec cells. Each command block either re-runs setup or uses the
    full `python3 '<runtime_dir>/cache_watch.py' … --ledger '<ledger_dir>'`
    form. It also forbids unquoted command-string expansion.
- **Summary:** failed sources are split into known and new failures, and the
  run stays `partial`. This is runbook guidance only; there is no CLI field.
- TDD evidence: 6 new or changed tests were RED for the expected reasons (a
  missing `keys`/`needs_decision`, an empty backlog, an accepted `@v1#`, a
  merge instead of a conflict, a registry without the quoting rule). All
  are GREEN after the change: the full suite ran 281 tests OK, 41 of them in
  cache-watch.
- Also added: a repeated identical unresolved conflict is recorded only once,
  so `finish-run` does not list duplicates. A test covers this.
- Edits: all through `apply_patch`. The 10 `sources.json` quoting hunks were
  generated by a short Python script into a patch file, then applied with
  `apply_patch`.
- Remaining risk: `unresolved_conflicts` is a report, not a gate. A
  coordinator that ignores it still loses that sighting until the source
  shows it again.

## Remaining risks

- Daily operation is unproven: the tests and the smoke run exercise the
  ledger, not real extraction quality or triage judgment.
- Coverage of bot-protected or JS-rendered sources depends on the fetch tools
  available at run time. Those sources will record `failed` or `partial`
  until the tooling succeeds.
- `fcntl` limits the ledger to POSIX hosts.
- High-frequency monorepo release pages (Vercel AI SDK, Mastra, LiteLLM,
  LMCache nightlies) rely on the extraction filters in the registry.
